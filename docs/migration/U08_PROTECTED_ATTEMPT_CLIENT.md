Backend exact qualified protocol 08e896c36b32a80ca440666087e55afa4f34ea28 (45801774818, 45801764133 PASS). Android development base 4c629decc57785c1af4f8e18e1ba977b01a290ff. Tracker jeresaf/data-collector#36, backend PR #37.

This first Android implementation adds strict versioned wire commitment framing, exact project URL derivation, typed no-store HTTPS reserve/bind/status client, immutable encrypted request/server journals and a preparation/reconciliation seam. The request UUID and local generation/package/ciphertext hashes are sealed before reservation; the server attempt, actor, project, form and wire commitment are sealed before binding. Resuming uses the same identity. New journal files, even incomplete/symlink markers, block the old editor/sender via the existing guard. Existing unbound transmission markers cannot be adopted. Status rechecks the actual sealed package and matches completed evidence to local bytes; returns no upload capability. No graphical caller, actual protected multipart transmission, local receipt publication or paired Android live acceptance yet. No background or automatic retry. A corrupt/partial journal remains conservatively blocked; durable directory synchronization and partial-journal recovery need qualification. Server reservation cannot be cancelled in this slice. Only JPEG/PNG supported by new wire protocol; existing WebP path is not broadened. A known independent SHA-256 vector matches the Java framing definition; CI must still execute Kotlin tests. Future implementation: opt-in sender and exact retransmit with sealed attempt; integrate receipts, UI and queue; real HTTPS/PG emulator, crash boundaries and tamper denial. No change to development branches or production feature flags.
